MM_GLB begins at `0x30007000`. It controls the C906 root path, multimedia buses and the MM UART source. UART3 is called **MM UART0** in these register field names.

## D0 root selection

| Field | Encoding | Selected path |
| --- | --- | --- |
| `MM_CLK_CTRL_CPU[10]` | 0 / 1 | RC32M / XTAL for MM_XCLK |
| `MM_CLK_CTRL_CPU[11]` | 0 / 1 | MM_XCLK / PLL path for the D0 root |
| `MM_CLK_CTRL_CPU[9:8]` | 0 | MM_MUXPLL_240M branch |
| | 1 | MM_MUXPLL_320M branch |
| | 2 or 3 | CPUPLL_400M branch |
| `MM_CLK_CTRL_CPU[12]` | 1 | D0 core clock enabled |

The PLL-path selector chooses a branch. Some branch parents have another selector in GLB. The branch's name alone does not establish its actual rate.

## Multimedia buses

`MM_CLK_CPU[7:0]` divides the D0 root. `MM_CLK_CPU[23:16]` controls MM_BCLK2X, and bits `[31:24]` control the independently selected MM_BCLK1X path. Divider updates use the XCLK path while requesting the D0/BCLK2X change, waiting for completion and restoring the parent selection.

## UART3 source

The MM UART selector is `MM_CLK_CTRL_CPU[5:4]`: 0 selects MM_BCLK1X, 1 selects MM_MUXPLL_160M, and 2 selects MM_XCLK. `MM_CLK_CTRL_PERI[19:17]` is its source divider; bit 16 enables that divider path.

The console setup chooses XTAL for MM_XCLK, selects MM_XCLK for UART, and uses divider encoding zero. UART3's own [bit-period register](/uart/registers/#uart-period) then sets the serial baud rate.

## M1s Dock boot readback

At the U-Boot prompt in the paired 2026-10-21 power-on and board-RESET
sessions, these values matched:

| Register | Address | Readback |
| --- | --- | --- |
| MM_CLK_CTRL_CPU | `0x30007000` | `0x45105d2f` |
| MM_CLK_CPU | `0x30007004` | `0x00010100` |
| MM_CLK_CTRL_PERI | `0x30007010` | `0x00810300` |

The selector fields decode to XTAL for MM_XCLK, the PLL path for the D0 root,
PLL-path encoding 1, and MM_XCLK for UART3. The D0 divider encoding is zero;
the UART3 source-divider encoding is zero with its enable bit set. These are
the recorded selector and divider settings, not measurements of PLL output.

See the [board context](/references/observations/#power-on-and-board-reset-readbacks)
for the comparison conditions. These values are post-boot state rather than
reset defaults.
